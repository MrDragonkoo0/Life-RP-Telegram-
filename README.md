# Life+ RP v0.3.0 — серверна реєстрація та SQLite

## Що додано
- Node.js + Express backend прямо в цьому проєкті.
- SQLite база даних через `better-sqlite3`.
- База за замовчуванням: `DB_PATH=/data/lifeplus.db` — підходить для Railway Volume.
- Реєстрація з нікнеймом і паролем.
- Паролі зберігаються на сервері у вигляді scrypt-хешу з унікальною сіллю.
- Серверні сесії з випадковим токеном, хеш якого зберігається в БД.
- Профіль: Telegram ID, нік, гроші, банк, рівень, XP, стать і позиція.
- Автоматичне збереження позиції/статі приблизно раз на 5 секунд під час гри.
- Профіль відновлюється після перезавантаження та нового деплою, якщо Railway Volume підключений до `/data`.

## Railway
У Variables вже має бути:

```text
DB_PATH=/data/lifeplus.db
```

Volume має бути змонтований у:

```text
/data
```

### Telegram безпека
Для справжнього запуску всередині Telegram потрібно додати Railway Variable:

```text
TELEGRAM_BOT_TOKEN=<токен твого Telegram-бота>
```

Сервер перевіряє `Telegram WebApp initData` криптографічно перед реєстрацією/входом. Не вставляй токен у код або frontend.

Для локального тесту браузером без Telegram дозволені тимчасові `local-*` ідентифікатори.

## Запуск
```bash
npm install
npm start
```

Після запуску відкрий `http://localhost:3000`.

## API
- `GET /api/health` — перевірка сервера та БД.
- `POST /api/register` — реєстрація.
- `POST /api/login` — вхід.
- `GET /api/profile` — поточний профіль.
- `PATCH /api/profile` — збереження дозволених даних профілю.
- `POST /api/logout` — завершення сесії.

## Важливо
Це v0.3.0. Код змінює клієнтську авторизацію з локального `localStorage` на серверну SQLite БД. Старі локальні профілі v0.2.0 автоматично не імпортуються.
